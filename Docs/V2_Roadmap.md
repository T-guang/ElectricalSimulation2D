# V2 开发路线

## 一、路线总原则

V2 不应推翻 V1 已稳定的规则系统，而是在 V1 的模板、端子、触点语义和教学化检查面板基础上，逐步补充动态状态、真实时间、参数计算和测量能力。

V1 的核心成果应继续保留：

- 静态拓扑分析；
- 家庭规则检查；
- 工业通用现象分析；
- 自由接线组合式判定；
- 检查面板教学化说明；
- 模板完整性检查。

V2 的新增能力应尽量以增量方式接入，避免重写 `CircuitStateAnalyzer`、`SimulationEngine`、`WireManager` 或模板保存格式。

## 二、V1.9 收口：文档、能力矩阵、测试结论

目标：

- 固化 V1.9 自由接线验收结果；
- 补充能力矩阵；
- 明确 V1 当前支持范围与边界；
- 为 V2 排期提供依据。

交付物：

- `V1.9_Free_Wiring_Acceptance_Result.md`
- `Supported_Circuit_Capability_Matrix.md`
- `V2_Roadmap.md`

结论：

- V1.9 通过后，当前系统可称为“V1 教学级通用现象判定稳定版”。

## 三、V2.0 RuntimeStateManager 动态运行状态框架

目标：

- 建立统一的运行态管理层；
- 明确“静态检查结果”和“历史运行保持状态”的边界；
- 为 KT 真实计时、自动往返虚拟运动、热继延时动作等 V2 能力提供基础。

建议能力：

- 统一管理接触器吸合保持状态；
- 统一管理电机 RUN、方向、运行阶段；
- 统一管理 KT 计时状态；
- 统一管理 SQ / 虚拟位置事件；
- 拓扑变化时安全清理旧运行态；
- 提供检查面板可解释的运行态摘要，但不反向污染静态拓扑判定。

依赖关系：

- KT 真实计时依赖 RuntimeStateManager；
- 自动往返虚拟运动依赖 RuntimeStateManager；
- 热继延时动作最终也需要 RuntimeStateManager 记录动作状态。

## 四、V2.1 KT 真实通电延时

目标：

- 将当前 KT 手动模拟延时升级为真实秒级通电延时；
- 保留手动模拟模式用于教学和测试；
- 支持通电后经过设定时间再切换 15/16、15/18。

建议能力：

- `delaySeconds` 参数；
- KT 线圈得电后开始计时；
- KT 线圈失电后复位；
- 延时未到：15/16 导通，15/18 断开；
- 延时到达：15/16 断开，15/18 导通；
- 检查面板显示“计时中 / 已到达 / 已复位”。

依赖关系：

- 依赖 V2.0 RuntimeStateManager。

不做内容：

- 不在此阶段做复杂参数计算；
- 不做断电延时 OffDelay 的完整工业级模型，除非单独立项。

## 五、V2.2 自动往返虚拟运动

目标：

- 让自动往返模板从“手动切换 SQ”升级为“虚拟运动触发 SQ”。

建议能力：

- 电机正转时虚拟位置向右移动；
- 电机反转时虚拟位置向左移动；
- 到达右端自动触发右 SQ；
- 到达左端自动触发左 SQ；
- 停止按钮 OFF 后虚拟运动停止；
- 检查面板解释当前方向、位置、SQ 触发原因。

依赖关系：

- 依赖 V2.0 RuntimeStateManager。

不做内容：

- 不做真实机械动力学；
- 不做负载惯量和运动曲线精确计算。

## 六、V2.3 参数计算基础版

目标：

- 建立教学级参数计算基础；
- 为电压表 / 电流表增强、热继延时动作、保护器件参数化提供依据。

建议能力：

- 基础额定电压识别；
- 简化电流估算；
- 简化功率估算；
- 电机额定参数字段展示；
- 基于模板 / 元件参数的教学级计算说明；
- 明确“估算值 / 教学值”与真实工业测量的区别。

依赖关系：

- 热继延时动作依赖参数计算，因此放在参数计算之后。
- 电压表 / 电流表真实测量增强依赖参数计算。

不做内容：

- 不做 SPICE 级仿真；
- 不做真实电磁暂态；
- 不做复杂电机模型。

## 七、V2.4 电压表 / 电流表测量增强

目标：

- 让万用表从基础联动升级为更接近真实教学测量；
- 支持学生在电路不同点位测量并获得合理解释。

建议能力：

- 两点电压测量；
- 三相线电压 / 相电压基础判断；
- 控制回路电压判断；
- 电流测量的基础支路估算；
- 测量点错误时提示“未形成有效测量回路”；
- 检查助手解释测量值来源。

依赖关系：

- 依赖 V2.3 参数计算基础版。

说明：

- 电压表 / 电流表真实测量属于参数计算阶段的重要内容。

## 八、V2.5 保护器件参数化与热继延时动作

目标：

- 让热继、熔断器、空开等保护器件从“手动状态”逐步升级为“参数驱动 + 延时动作”。

建议能力：

- 热继整定电流；
- 电机负载电流估算；
- 过载后延时动作；
- 热继动作后 95/96 断开；
- 复位逻辑；
- 熔断器 / 空开基础参数说明。

依赖关系：

- 热继延时动作依赖 V2.3 参数计算；
- 动作状态管理依赖 V2.0 RuntimeStateManager。

不做内容：

- 不追求完整工业保护曲线；
- 不做复杂热模型。

## 九、V2.6 更多工业模板

目标：

- 在 V1 和 V2 基础能力稳定后，扩展更多教学模板。

候选模板：

- 更完整的星三角启动教学模板；
- 多台电机顺序控制扩展；
- 反接制动 / 能耗制动基础版；
- 液位控制基础版；
- 皮带输送顺序控制；
- 简化故障排查模板。

暂不做：

- PLC；
- 双速电机；
- 复杂变频器；
- 工业通信；
- 大规模工厂级系统。

说明：

- 新模板必须先通过 Template Integrity Checker；
- 新模板应优先复用已有元件和规则原语。

## 十、V2.7 “AI 助教”改名为“检查助手”并增强解释

目标：

- 将“AI 助教”定位调整为“检查助手”；
- 减少用户对大模型自由发挥的误解；
- 强化“基于规则系统确定事实进行解释”的产品边界。

建议能力：

- 面板标题改为“检查助手”；
- 用教学语言解释规则系统已经确定的事实；
- 对静态分析与画布历史 RUN 的差异给出清楚说明；
- 对错误接线给出修正建议；
- 对已知边界提示“当前版本暂不支持”。

重要原则：

- 检查助手只解释规则系统确定的事实，不替代规则系统；
- 不让检查助手编造电气结论；
- 不让检查助手绕过 `CircuitStateAnalyzer` 或家庭规则检查器直接判定电路；
- 不把不确定内容说成确定结论。

## 十一、暂不纳入 V2 的事项

- 练习评分暂不做；
- PLC 暂不做；
- 双速电机暂不做；
- ngspice 暂不接入；
- 工业级物理仿真暂不做；
- 完整电机转矩 / 转速 / 温升模型暂不做；
- 复杂保护曲线暂不做。

## 十二、建议实施顺序

1. 完成 V1.9 文档收口；
2. 实现 V2.0 RuntimeStateManager；
3. 基于 RuntimeStateManager 实现 V2.1 KT 真实通电延时；
4. 基于 RuntimeStateManager 实现 V2.2 自动往返虚拟运动；
5. 实现 V2.3 参数计算基础版；
6. 在参数计算基础上增强 V2.4 电压表 / 电流表；
7. 在参数计算与运行态基础上实现 V2.5 热继延时动作；
8. 扩展 V2.6 更多工业模板；
9. 将“AI 助教”收口为 V2.7 “检查助手”。

## 十三、风险控制

- 每个阶段都应保留 V1 模板回归测试；
- 不应一次性重构核心系统；
- 不应改变模板保存格式，除非有迁移方案；
- 不应让动态运行态污染静态检查结论；
- 不应为单个模板写死全局规则；
- 新增能力必须能解释给学生听。
