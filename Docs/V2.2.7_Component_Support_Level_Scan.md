# V2.2.7.0 元器件支持等级与未支持元件提示机制扫描

## 一、扫描目标

本次扫描用于区分：

```text
控件池里存在 ≠ 仿真规则已支持
```

当前系统已经具备 V1.9 自由接线通用性验收、V2.0 RuntimeStateManager、V2.1 KT 真实通电延时、V2.2 自动往返虚拟运动能力。但控件池和 Data asset 中还包含 PLC、步进、断电延时、开关电源、端子排、指示灯等尚未完全进入标准模板和规则系统的元件。

本阶段只做扫描与设计，不修改运行逻辑。

## 二、当前工程现状

`ComponentDefinition` 当前已有：

- `sourceVoltage`
- `sourceLineVoltage`

- `ratedCurrent`
- `maxVoltage`
- `maxCurrent`

## 三、当前规则覆盖情况

### 1. SimulationEngine 已支持或部分支持

- 电源、开关、双控、按钮、空开、熔断器、端子排的内部导通。
- 接触器 A1/A2 线圈、主触点、13/14 自锁、21/22 互锁。
- OnDelay KT 真实通电延时，15/16 与 15/18 自动切换。
- SQ 行程开关 11/12、23/24，自动往返中支持虚拟限位 effectiveTriggered。
- 三相电机运行、正反转方向。
- 星三角电机星形、三角、冲突阻断。
- 热继主触点与 95/96 保护触点基础逻辑，另有过载/跳闸雏形。
- 端子排作为连接器导通。

### 2. CircuitStateAnalyzer 已支持或部分支持

- 电压标签传播：L/N/L1/L2/L3/PE/Conflict。
- 家庭负载 L-N 判断。
- 接触器线圈、主触点、自锁、互锁。
- KT 状态说明。
- SQ 状态说明。
- 热继保护触点说明。
- 普通三相电机缺相、重复相、正反转。
- 星三角星形、三角、冲突危险优先。
- 刀开关有识别函数，但未形成完整模板验收。

### 3. WireManager 特殊接线规则

- 默认禁止同元件端子互接。
- 当前只允许 `Motor_StarDelta_380V` 的 U/V/W 六端子跳线。
- 端子排属于内部导通连接器，不通过同元件外部跳线实现。

### 4. 检查面板 / 检查助手特殊说明

- 已有家庭检查、工业分析、KT、星三角、热继、自锁历史边界、自动往返虚拟运动说明。
- 尚无“未支持元件”统一扫描提示。

## 四、建议支持等级定义

### Level 0：VisualOnly

可以拖出、接线、保存，但不参与仿真判断。

### Level 1：ConnectorOnly

连接器或端子类，只做接线中转，不产生动作。

### Level 2：SimpleSwitchSupported

只需要 ON/OFF 触点导通/断开即可基本支持。

### Level 3：RuntimeSupported

已参与 SimulationEngine / CircuitStateAnalyzer 的运行或规则判断。

### Level 4：DynamicRuntimeSupported

有真实时间或虚拟运动状态。

### Level 5：ParameterCalculationSupported

可参与后续电压、电流、功率、过载等教学估算。

一个元件可拥有多个能力，文档表中按当前或近期最高支持等级记录，并在备注中说明实际边界。

## 六、未支持元件清单

### 1. 完全未支持仿真判断

- `PLC_Output_24V`
- `StepperDriver_24V`
- `StepperMotor_24V`
- `SwitchPower_220V`
- `Timer_OffDelay_220V`
- `Timer_OffDelay_380V`

### 2. 部分支持但容易误导

- `SolenoidValve_24V`
- `Indicator_*`
- `KnifeSwitch_QS`
- `LimitSwitch_SelfLock`
- `Button_SelfLock_*`
- `Breaker_1P`
- `Breaker_4P`
- `Fuse_1P`
- `Contactor_KM_220V`
- `Timer_OnDelay_220V`

### 3. 有参数但运行规则不完整

- `SwitchPower_220V`：有 24V 输出字段，但未实现 24V 输出传播。
- `StepperMotor_24V`：有额定参数，但无步进电机运行模型。
- `SolenoidValve_24V`：有额定参数，但无阀动作模型。
- `Timer_OffDelay_*`：有额定参数，但无断电延时触点模型。

### 4. 有端子但无内部业务语义

- `PLC_Output_24V`
- `StepperDriver_24V`
- `StepperMotor_24V`
- `SwitchPower_220V`
- `Timer_OffDelay_*`

### 5. 高风险误判元件

- `StepperMotor_24V`：`kind=Motor`，但端子是 `A+/A-/B+/B-`，不是三相电机。
- `SwitchPower_220V`：看似应产生 24V 输出，但当前没有转换规则。
- `Timer_OffDelay_*`：看似 KT，但当前未实现断电延时触点。
- `PLC_Output_24V`：看似可控制输出，但无 PLC 状态语义。

## 七、控件池提示方案

建议在控件池中加入轻量标签：

```text
步进电机（暂未支持仿真）
PLC输出模块（可接线，暂不判断动作）
断电延时继电器（规则待实现）
端子排（连接器）
```

标签建议采用灰色小字或浅色角标，不要把控件置灰到不可用。目标是提醒“可以画图，但规则未完整支持”。

## 八、画布元件提示方案

当用户拖入未支持元件时，在状态标签或选中提示中显示：

```text
暂未支持仿真
```

对连接器类显示：

```text
连接器：仅用于接线中转
```

对部分支持类显示：

```text
部分支持：仅判断基础触点
```

## 九、检查面板提示方案

如果画布包含未支持元件：

```text
当前电路包含暂未支持仿真判断的元件：步进电机、PLC输出模块。
系统可以保存接线并展示连接，但不会判断该支路是否正常运行。
```

如果未支持元件接入主要运行路径：

```text
已支持部分未发现明显问题，但由于存在暂未支持元件，系统无法给出完整运行结论。
```

第一版建议只做“存在提示”。后续再做“是否接入主路径”的降级判断。

## 十、参数计算衔接方案

V2.3 参数计算时建议只对支持参数计算的元件启用：

- 电源
- 灯泡
- 风扇
- 三相电机
- 星三角电机
- 空开
- 熔断器
- 热继

对未支持元件提示：

```text
该元件当前未纳入教学参数估算。
```

不要对 PLC、步进、开关电源、断电延时继电器等元件乱算电流。

## 十一、建议新增字段

建议在 `ComponentDefinition` 中新增：

```csharp
public ComponentSupportLevel supportLevel;
public string unsupportedReason;
public bool canParticipateInRuntime = true;
public bool canParticipateInParameterCalculation;
```

建议新增枚举：

```csharp
public enum ComponentSupportLevel
{
    VisualOnly = 0,
    ConnectorOnly = 1,
    SimpleSwitchSupported = 2,
    RuntimeSupported = 3,
    DynamicRuntimeSupported = 4,
    ParameterCalculationSupported = 5
}
```

低风险第一版也可以只加：

```csharp
public ComponentSupportLevel supportLevel;
public string unsupportedReason;
```

`canParticipateInParameterCalculation` 可等 V2.3 参数计算正式开始时再加。

## 十二、是否需要修改模板或保存格式

不建议修改模板 JSON。

不建议修改保存 DTO。

支持等级是元件定义元数据，应放在 Data asset，而不是用户图纸或模板连接数据中。

## 十三、实现风险

1. 新增 `ComponentDefinition` 字段会导致所有 Data asset 序列化变化，diff 较大，但模板加载风险低。
2. 按 `ComponentKind` 自动推断支持等级容易误判，例如步进电机也是 `Motor`。
3. 未支持元件未接线时不应导致整图失败。
4. 未支持元件接入主路径时，第一版不宜做复杂路径判断，可先提示“存在未支持元件”。
5. 控件池提示不要过度吓人，避免用户误以为系统不可用。
6. V2.3 参数计算必须利用支持等级，否则会对未支持元件产生错误估算。
