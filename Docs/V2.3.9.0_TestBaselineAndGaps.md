## 二、测试保护能力评估

### 1. 对于 CircuitValidationService 和 Helper
- **当前状态**：已经有基础的单元测试，并且**真实调用了验证逻辑（Helper）**。
- **不足**：目前的测试主要基于代码组装假数据（伪造模型，Fake components/wires），并未跑在完整的 `CircuitStateAnalyzer` 拓扑上，难以完全模拟真实由于电位传播异常引发的短路或状态重叠。**能拦截明显的规则逻辑错误，但难以防止正常模板场景下的深层误报。**

### 2. 对于 CircuitStateAnalyzer
- **当前状态**：**无单元测试保护。** `CircuitStateAnalyzer` 这个最庞大、最核心的类，目前仅能通过 `SimulationEngine` 在运行时的表现进行纯人工黑盒测试。
- **结论**：**当前绝对不足以对 `CircuitStateAnalyzer` 的核心图遍历和推导逻辑进行重构。**

### 3. 对于 LocalInspectorPanel
- **当前状态**：无测试保护。完全依赖于 Unity 编辑器内的 Play Mode 人工点击查看。
- **结论**：目前仅有 `DemoSceneBuilder` 可以快速搭建预设场景，帮助开发者**人工**验证 Inspector 面板的输出，但缺少自动化基线比对（Snapshot Testing）。

## 三、重构前缺失的关键测试基线（缺口）

若要安全开启下一阶段的重构，必须先补充以下基线：

1. **真实模板快照测试 (Snapshot Tests for Real Templates)**
   - 需要一个工具：自动加载当前已知正常的所有 JSON 模板。
   - 调用 `CircuitStateAnalyzer` 和 `CircuitValidationService`，收集其产生的完整输出（包括故障集合、中文报告）。
   - 将输出序列化为 `.txt` 或 `.json` 文件并加入 Git。重构后比对这些文件，以确保原本不出错的模板不会因为重构而发生误报。

2. **Analyzer 图连通性黑盒测试**
   - 不测试内部的方法，仅对几条经典的线圈、断路器、电机的通路给定期望的电位值（比如 L 或 N），断言推导结果。

3. **UI 逻辑剥离的隔离测试**
   - `LocalInspectorPanel` 在抽离出 `ReportFormatter` 之后，需要对 Formatter 补充纯字符串组装的 Unit Test。

---
**当前行动建议：**
由于测试匮乏，**极其危险的核心类 (CircuitStateAnalyzer)** 目前绝对不能动内部逻辑。任何重构的第一刀，必须从纯字符串的迁移或已经有部分 Helper 测试的区域切入。
